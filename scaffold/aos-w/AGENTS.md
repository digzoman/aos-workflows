# AOS-W Installed Framework — Start Here

You are reading a portable **Agent OS Workflows** installation, which can be operated without Python, Git, MCP, a cloud server or a plugin.

1. Read \`README.md\`, \`VERSION.json\`, \`PROTOCOL.md\`, \`agent-files/README.md\` and \`agent-files/config/settings.json\`.
2. Locate the intended workflow under \`agent-files/instances/\`, its latest immutable \`graph-revisions/\`, selected \`runs/<run-id>/run.json\`, \`state.json\`, \`events.jsonl\`, \`handoff.json\` and \`handoff.md\`.
3. Follow the **saved pinned graph**, current real history and permissions. Do not rely on conversation memory, mutable template HEAD or old visualization snapshots.
4. A capability label is **not an excuse to stop**. Discover existing tools, browser, files and trusted skills; use authorized alternatives and carry forward independent tasks. Never invent an ad hoc human gate. See \`references/CAPABILITY-RECOVERY.md\`.
5. Real independent reviews, verified image inspection and consequential external permissions must still be truthful and valid. A review PASS never authorizes a Meta campaign launch, spend change or sending messages.
6. **Only write in \`agent-files/\`** in normal workflow operation. Framework and base template files are protected and only change on an explicit versioned upgrade.
7. For a human-friendly flow, read \`references/HUMAN-FIRST.md\` and \`references/VISUALIZATION.md\`; create standalone interactive HTML under \`agent-files/visualizations/\`, not in a ZIP unless forced by the host.
8. If using GitHub for viewing, a GitHub code file link is not a rendered webpage. Offer an actual host preview, authorized/sanitized GitHub Pages URL, or individual HTML file. Never publish raw private workflows or claim a link is rendered without testing it.

Follow the highest-priority user/host instructions in addition to these pointers. This file provides discoverability, not extra permissions.
